# Nokia 3310 黑色交互展台

完整的技术栈、模型处理、网页加载与按键原理见 [项目总览](../README.md)。本文侧重构建、预览和发布命令。

网页源码最初取自 2026-10-03 的实际线上发布目录。`main` 已合入这份网页，模型源文件仍保留在 `Blender工程/`。页面提供拖动旋转、缩放和 15 个按键的按压动画、局部明暗及短音；屏幕仍是模型内的静态点阵，不包含真实手机系统或拨号。

## 日常构建与本地预览

Windows 最简单的方式：在项目根目录双击 **`启动本地预览.cmd`**。

它会自动找到当前用户的 Codex Python 运行环境（没有时尝试 Windows `py -3`），构建最新文件并打开默认浏览器，无需手动输入 Python 路径。默认使用 8000 端口，被占用时自动选择空闲端口；不会关闭已经运行的服务。预览期间保留启动窗口，关闭窗口或按 Ctrl+C 停止。源码或模型修改后，关闭旧窗口，再双击启动即可重新构建。

命令行方式需要 Python 3.10+，仅使用标准库。在仓库根目录运行（Windows 有 Python Launcher 时将 `python3` 换成 `py -3`）：

```sh
python3 web/build.py --serve 8080
```

打开 http://127.0.0.1:8080/。预览服务仅监听本机，关闭缓存，按 Ctrl+C 停止。不能直接双击 HTML，网页使用根路径资源。

修改 `web/app.js`、`web/appearance.js`、`web/style.css` 等源码，或从 Blender 重新导出 `Blender工程/网页模型/nokia3310_interactive_v2.glb` 后，重新运行构建并刷新浏览器即可，无需更新旧发布版的哈希。棚拍、材质变化时也运行 `Blender工程/脚本/导出网页棚拍配置.py` 更新 `web/assets/studio.json`。若预览服务仍在运行，可在另一个终端单独构建：

```sh
python3 web/build.py
```

这是一次性构建，不会监听文件变化；构建不会修改 Blender 工程、源 GLB、Git 分支或 VPS。

可指定另一个待预览的模型：

```sh
python3 web/build.py --model /path/to/new-model.glb --serve 8080
```

构建结果位于 `web/dist/`。`build-manifest.json` 记录这次实际生成的 16 份运行资源的大小和 SHA-256，方便与部署文件核对；它不代表已经发布，也不对自身求哈希。源码输出统一使用 LF，避免 Windows Git 换行转换造成复现差异。GLB 和依赖文件按原始二进制字节复制。

## 材质主题与棚拍

左上角提供“经典实体 / 玻璃棚拍”滑动开关，支持点击、拖动、Space/Enter 和左右方向键。默认实体主题无透射和自发光；玻璃主题使用 Blender 的 AgX、IOR、薄膜参数及五盏灯的环境图近似。两个主题共用模型、相机和按键动画；这是外观选择，尚未接入展示／使用模式或动态屏幕。

`appearance.js` 集中处理颜色与光照，`theme-switch.js` 处理开关交互。环境图仅生成一次，静止时停止渲染；DPR 上限 1.5，透射目标比例 0.65。WebGL 与 Cycles 的光线路径不同，网页专门校准了有效折射厚度；不能将当前实现描述为两种渲染器逐像素一致。

按键行程倍率在 `interaction.js` 的 `PRESS_TRAVEL_SCALE`（当前 1.35）；键帽的局部明暗在 `appearance.js` 的 `setKeyFeedback()`；短音参数在 `key-sound.js`。声音默认开启，可用主题开关右侧的按钮静音，偏好保存在本机。只有有效轻触发声，拖动旋转时不会发声。无需下载音频素材，声音合成失败时不影响按压。

## 外部依赖仍严格锁定

`dependencies.lock.json` 只负责 Three.js 依赖，不再锁死项目源码或模型。当前版本为 `0.180.0`：

- 首次构建从 npm 官方 registry 下载 tarball，校验 SHA-512，以及清单中各文件的 SHA-256。
- 只读取允许列表中的六份运行时 JS 和 MIT 许可证，不运行安装脚本，不解压任意归档路径。
- 验证通过的 tarball 缓存在 `web/.cache/`，后续可离线构建；每次使用缓存仍重新校验。
- 校验失败就停止，不自动升级、不绕过校验；输入校验失败时保留原有 `dist` 内容。

也可显式提供离线包：

```sh
python3 web/build.py --tarball /path/to/three-0.180.0.tgz
```

`dist/`、`.cache/` 和 Python 缓存均不提交 Git。浏览器运行时依赖由本地预览服务或网站自身提供，不依赖第三方 CDN。

## 核对 2026-10-03 的历史发布版

`release-snapshots/20261003-black.json` 独立保留当时全部 12 份运行资源的哈希及源提交 `b60447d580e5b99ad4011c843019405182f5f1e3`。它是历史记录，日常开发不要重写：

```sh
python3 web/build.py --verify-snapshot web/release-snapshots/20261003-black.json
```

该选项核对当前源码、模型和依赖能否生成历史版的相同运行资源；有实质改动时应失败。它不会自动回退或覆盖源码。需要重新构建旧版时，在另外的检出目录使用保留的 `deploy/black-viewer-20261003` 分支即可；不要为通过历史校验而改写快照。新版额外生成的 `build-manifest.json` 不在历史运行资源清单内。

## 修改与发布流程

1. 从同步后的 `main` 建立功能分支，修改源码或模型。
2. 本地构建，检查显示效果、按键与目标设备表现。
3. 提交并推送代码，确认后再合并。
4. 明确要发布时，将已验证的 `web/dist/` 内容复制到新的服务器发布目录，再切换站点目录，保留上一版以便回退。

构建脚本不含 SSH、上传、自动部署或服务器配置修改。Git 推送与网站发布是两个独立操作。网页必须部署在域名根目录；不要把 Blender 工程、源模型目录或整个 Git 仓库作为公开网站根目录。

Cloudflare 会缓存静态资源。当前版本 `20261004-feedback-3` 已用于 HTML 的 CSS/JS 链接、应用模块导入、GLB 和棚拍 JSON 地址。后续发布修改过的资源时，应同步更新 `index.html` 与 `app.js` 中的版本参数，避免新页面混用旧脚本或旧模型；固定版本的 Three.js 不变。发布验证应核对这些带版本参数的实际请求。

## 验证

```sh
python3 -m unittest discover -s web/tests -v
node --test web/tests/test_feedback.mjs
```

测试覆盖修改源码/替换模型后的开发构建、历史版一致性、Windows 换行、快照失败保留旧输出、依赖及缓存完整性、输出路径边界，以及预览端口冲突时不共享端口并自动选择空闲端口，全部离线执行。

Node 测试需先构建，直接读取当前 GLB 的按压轨道，验证 15 键新增行程、回位、原始动画不被改写、连续点击后的复位与误触过滤。实际浏览器中的局部材质、静音、音频合成与资源检查见 `tests/feedback-validation.json`；它与旧版 `browser-validation.json` 分开保存。

原部署记录还包含 15 个按键射线命中、动画回位、拖动/多指误触过滤与四种视口比例的检查。这些是 2026-10-03 版本的记录，不能替代今后每次改动后的实际浏览器验收，也不是实际手机硬件上的性能测试。模型和参考资料的来源与使用许可需另行核实。
